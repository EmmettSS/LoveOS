# LoveOS

> یه سیستم‌عامل کوچولوی عاشقانه توی مرورگر — ساخته‌ی بابا، برای دخترش.
> A tiny romantic operating system in the browser — built by Daddy, for his daughter.

![version](https://img.shields.io/badge/version-2.0-ec4899) ![backend](https://img.shields.io/badge/backend-Django%205%20%2B%20DRF-0C4B33) ![frontend](https://img.shields.io/badge/frontend-React%2019%20%2B%20Vite%208-61DAFB)

۳۰ اپ کوچک، یک دسکتاپ، یک پنل که همه‌چیزش از آن‌جا عوض می‌شود: پیام‌ها، ویس‌ها، نامه‌ها،
کوییزها، هدیه‌ها، کتاب‌ها، کلمه‌های زبان و حتی رازها.

## راه‌اندازی در یک نگاه

```bash
# بک‌اند
cd backend && python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env && .venv/bin/python manage.py migrate
.venv/bin/python manage.py seed_loveos        # رمز ورود: 1234 · صندوقچه: 0000
.venv/bin/python manage.py runserver 0.0.0.0:8000

# فرانت‌اند (ترمینال دوم)
cd frontend && npm install && npm run dev     # http://localhost:5173
```

## جلوه‌های سه‌بعدی و لایه‌ی کیفیت

پوسته‌ی سه‌بعدیِ LoveOS چهار لایه دارد و **هیچ‌وقت با یک صفحه‌ی سفید یا یک
گوشیِ کند تنبیه‌ات نمی‌کند** — اگر دستگاه نتواند، خودش یک پله پایین می‌آید:

| انتخاب | نام | چه می‌بینی |
|---|---|---|
| `auto` | خودکار | دستگاه سنجه می‌شود (هسته، حافظه، WebGL، نسبتِ پیکسل، فریمِ واقعی) و خودش لایه را برمی‌گزیند |
| `lite` | مهتاب | عمقِ «نقاشی‌شده»: سایه، پخ و گرادیان — بدونِ هیچ چرخشِ سه‌بعدی |
| `balanced` | بلور | چرخشِ CSS، تیلت با نشانگر/ژیروسکوپ، برجسته‌سازیِ لایه‌ای |
| `dream` | کهکشان | همه‌ی بلور + WebGL واقعی (آسمانِ ستاره‌ها، سالنِ سینما، ماکتِ خانه) و کره‌ی زمین روی نقشه |

این لایه روی **هر ۳۰ اپ** نشسته است، نه فقط چندتایشان. ولی یکسان نشسته
نیست، چون اپ‌ها یکسان نیستند:

* **لحظه‌ی امضا** (۱۲ اپ) یک جسمِ سه‌بعدیِ اختصاصی دارند که هویتِ همان اپ
  است: قلبِ چندلایه، نوارِ کاست با قرصِ چرخان، مدالِ فلزی، صفحه‌ی
  گرامافون، سالنِ سینما، ماکتِ خانه، کره‌ی زمین.
* **عمقِ خویشتن‌دار** (۹ اپِ داده‌محور مثلِ تماس، چرخه، پلِ زبان،
  کتاب‌خوانی) فقط عمقِ نقاشی‌شده و یک نقطه‌ی کانونی می‌گیرند. سطرهای داده،
  جدول، تقویم و فرم **هرگز کج نمی‌شوند** و منطقِ اپ دست‌نخورده می‌ماند.
* **ترمینال** یک استثنای عمدی است: شیشه‌ی CRT با انحنای گوشه و فسفرِ
  درخشان، چون خودش یک نمایشگرِ قدیمی است.
* **چهار روکشِ سیستم** (منوی استارت، مرکزِ اعلان، جست‌وجوی سراسری، روکشِ
  راز) با ورق‌خوردنِ سه‌بعدی باز می‌شوند — آن‌هایی که از پایین می‌آیند با
  چرخشِ منفی و جست‌وجو که از بالا می‌آید با مثبت.

نکته‌های طراحی که عمداً رعایت شده‌اند:

* **متن هرگز کج نمی‌شود.** تیلت فقط روی عناصرِ بصری است (قلب، گیاه، عکسِ
  خاطره، جعبه‌ی هدیه) و نه روی ظرفِ متن یا ناحیه‌ی اسکرول.
* **یک منبعِ نورِ ثابت** بینِ همه‌ی اپ‌ها (`--light-x` / `--light-y`) تا فضای
  فیزیکی منسجم بماند.
* **نگهبانِ فریم:** اگر در کهکشان فریم واقعاً افت کند، یک پله تنزل می‌دهد و
  آن را برای نشستِ بعد هم به خاطر می‌سپارد.
* **احترام به `prefers-reduced-motion`:** سقفِ مهتاب.
* **`three.js` با `lazy()` در یک چانکِ جدا** است و از `precache` هم مستثنی
  شده؛ کاربرِ مهتاب هرگز دانلودش نمی‌کند. سه صحنه‌ی WebGL روی هم ۵۶۲
  کیلوبایتِ خام‌اند و هیچ‌کدام در `precache` نیستند.
* **سقفِ دو صحنه‌ی زنده:** هر `WebGLRenderer` یک contextِ جدا روی GPU است،
  پس اگر صحنه‌ی سوم هم‌زمان خواسته شود `onUnavailable('budget')` می‌گیرد و
  اپ به تنزلِ CSS می‌رود — سالنِ سینما و ماکتِ خانه هر دو پوسته‌ی CSSِ
  کامل دارند.
* نقشه روی GPU خانواده‌ی **Mali** کره را روشن نمی‌کند (باگِ شناخته‌شده‌ی
  دقتِ عرضِ جغرافیاییِ maplibre در projection کره‌ای).

جایِ انتخابش: **تنظیمات ← جلوه‌های سه‌بعدی**. همان‌جا هم نوشته «الان» کدام
لایه فعال است و هم چرا (دلیل‌ها از خودِ موتور می‌آیند، نه یک متنِ ثابت).

## تست

```bash
cd backend && .venv/bin/python manage.py test          # ۹۷ تست
cd frontend && npx tsc -b && npx oxlint src && npm run build && npm run test:ui
                                                        # ۱۰ سوئیت · ۳۲۶ بررسی
```

دو سوئیتِ اختصاصی برای همین لایه‌ی سه‌بعدی هست، چون دو جور باگ داریم:

* **`depth-tiers`** (۷۱ بررسیِ رندری) هر سه لایه را روی اپ‌ها اجبار می‌کند
  و از جمله می‌سنجد که گرادیانِ `id="hb"` دقیقاً یک بار در سند باشد، متن‌ها
  داخلِ ظرفِ تیلت نباشند، نبودِ WebGL به تنزلِ باوقار برسد نه صفحه‌ی سفید، و
  سینما در نبودِ WebGL سالنِ CSS نشان دهد نه بومِ سیاه.
* **`three-hygiene`** (۲۹ بررسیِ ایستا) روی متنِ منبع کار می‌کند، بدونِ
  jsdom، زیرِ یک ثانیه — برای قاعده‌هایی که jsdom هرگز نمی‌بیندشان: نبودِ
  نقضِ Rules-of-Hooks، بسته‌شدنِ کلیدهای سه‌بعدی در هر سه شاخه‌ی framer،
  نرفتنِ `/src/three/` به `manualChunks`، و اینکه هر صحنه‌ی تازه هم در
  `globIgnores` باشد هم در `urlPattern`. هرکدام از این‌ها یک باگِ **واقعاً
  رخ‌داده** در همین پروژه است، نه قاعده‌ی حدسی.
  چهار بررسیِ آخرش **گاردِ پوشش** است: هر اپِ `src/apps/*.tsx` باید دستِ‌کم
  یک نشانگرِ عمق داشته باشد، پس اپِ سی‌ویکمِ تخت build را می‌شکند. وعده‌ی
  «کلِ پروژه سه‌بعدی شد» دیگر با یک حلقه‌ی دستیِ shell سنجه نمی‌شود.

یک سوئیتِ ایستایِ سوم هم هست که از دلِ همین فاز بیرون آمد: **`i18n-keys`**
(۳۱ بررسی). موتورِ کیفیت یک ماژولِ خالصِ بیرونِ React است و هوکِ ترجمه
ندارد؛ نسخه‌ی اول دلیل‌هایِ «چرا این لایه؟» را به‌صورتِ **رشته‌ی فارسیِ
آماده** در store می‌گذاشت، پس با عوض‌شدنِ زبان به انگلیسی کلِ صفحه انگلیسی
می‌شد ولی همان یک فهرست فارسی می‌ماند. حالا موتور فقط کلید و آرگومان
می‌سازد و ترجمه در زمانِ رندر انجام می‌شود — و این سوئیت نگهبانِ همان
جفت‌شدگی است، به‌علاوه‌ی برابریِ کاملِ دو زبان (۶۸۶ کلید)، یکی بودنِ
جای‌نماهایِ `{{…}}`، وجودِ هر ۵۴۰ کلیدِ مصرف‌شده در کد، عنوانِ هر ۳۰ اپ، و
ساختارِ آرایه‌ی `boot.lines` (که `label`ش **بدونِ گارد** خوانده می‌شود).
